# 最终实验版本与执行计划

| 组别 | 结果记录数 |

R28 比较保留原先 8 条主要记录、4 条补充记录与 N10/N20/N40 的 6 条记录，包括 R28-N5-F50-C2。

## 数据集与用例命名

数据集统一为 `R3_N5`、`R12_N5`、`R28_N5`、`R28_N10`、`R28_N20`、`R28_N40`。
各目录为 `data/<数据集名>_data/`，`scenarioCfg.txt` 只列该数据集的场景，数量和顺序明确。
F 和 C 是运行参数；完整用例名称为 `R28-N5-F50-C2`。历史搜索编号仅保留在内部来源映射。

新目录保留原选定场景及基础数据的字节。场景清单裁剪为实际选用的 N 个场景，概率写为 1/N；这与原程序实际使用的均匀概率一致。
`datasets.json`、`cases.json` 保存文件哈希、旧名称映射、参数和内容指纹。

## 消融关系

- VI 配对：同一输入、Lifted 算法、执行文件和所有参数，仅 `--valid-inequality` 不同。
- Full/L2P 配对：同一输入、执行文件和所有参数，仅 `--alg` 不同；保留原有增强模块差异。
- 共用 1% 全局停止精度、7200 秒软预算和 12 线程预算，场景并行统一为 3×4。
- RSP 返回 NUMERICAL 时跳过该次筛选，不据此加割；原问题子问题照常验证。四种分解算法共用该策略。
- 原问题子问题、主问题的异常状态仍按实际状态结束并保存原问题界；不会将其视为成功验证。
- 保留既有 EF 专用外部内存保护；其余算法没有新增外部内存保护或硬超时。

## 代码与结果

`release.json` 绑定真实源码提交、源码字节、执行文件和 COPT DLL 哈希。
`bin/wireless.exe` 为该冻结源码构建的执行文件。COPT DLL 来自本机安装，不随仓库分发。
运行时从仓库根目录读取 `solverCfg.txt` 和 `data/`；不依赖编译机器的绝对源码路径。

`history/` 保存重跑前选用的原始日志、输入快照、三种归档源码与执行文件、以及中断记录。
这些日志保留实际版本关系，不代表由本次最终版本生成。旧版复编译的字节等价验证尚未通过，记录已保留。
新的正式结果将写入 `runs/`，每条记录保存源码提交、执行文件哈希、命令、实际墙钟时间、终止状态、资源和原始日志。
`results.html` 按三组显示数值与缺失状态，使用两行用例/指标表头；运行时自动更新，`results.json` 保存对应记录。
队列结束后，还要独立核对三组原始证据并生成最终表格。

## 执行顺序

1. 完成最终代码、输入和配对校验，Release 编译并验证输出。
2. 提交代码、用例、历史选用日志及版本证据到远程，锁定执行文件。
3. 按 R3 主表、R12 主表、VI、R28 主表与其余 R28 配对的顺序串行执行。
4. 独立核对每条最终记录的原始界、状态、时间、迭代与输入版本，更新远程日志。
5. 主表使用算法行、R3/R12/R28 分组及两行用例/指标表头；每个 F 列组为 LB、UB、actualTime(s)。

写作可先进行模型、算法、用例与实验设置部分；数值比较按新结果核对后更新。
